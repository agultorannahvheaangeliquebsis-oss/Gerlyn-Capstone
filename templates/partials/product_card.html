{% comment %} The storefront's product card — ONE definition, used by every grid that draws one: the catalog grid (partials/catalog_grid.html, which also re-renders through it on every live-search keystroke) and the home page's "More to Discover" grid (partials/home_content.html). It lives here because the two grids had drifted: the catalog card carried a description line and the home card did not, so the same product was a four-line card on one page and a three-line card on the other, at different heights, in the same .pgrid. Included with `product=`, so a caller iterating rows passes row.product and a caller iterating products passes p. Hierarchy, top to bottom: category → name → social proof → price + action Deliberately not drawn, because there is no field behind them and a card is the easiest place in a storefront to state something the store never said: · the wishlist heart — no wishlist model; a button that does nothing is worse than no button · the ★★★★☆ rating — no review model. The "N sold" line takes that slot instead, and it is a real SalesItem sum (inventory/stats.py), shown only when non-zero · the struck-through price — Product has one retail price. A fake "was" price is a false discount claim, not styling · the BULK RATE flag — wholesale_price is a real second price, but a corner flag on the card only says one exists without saying what it is. The product page states the actual figure, which is the useful form of it · a brand line — Product has no brand/manufacturer column There is no stock badge and no out-of-stock state at all here: both callers filter to in-stock products before rendering (inventory.stats. in_stock_product_ids), so every card that renders is a card you can buy from. {% endcomment %} {% load shop_extras %}
