{% comment %} Record Payment dialog — Order Detail and the Billing record's own page both include this. Hidden by CSS until static/js/order-detail.js opens it from an [data-payment-open] link, which is also a plain link to the full-page form (billing_create) for when that script has not run. Needs from the view: transaction, billing (may be None), payment_choices, reference_required_methods, proof_required_methods, proof_max_mb, and return_to ('order' or 'billing' — which page to bounce back to; defaults to 'order' for callers that don't pass it). It posts to billing_create with return_to, so the caller lands back on whichever page it opened this from — with a message either way. Nothing here is authoritative: billing_create re-checks the method against the order's channel, the reference format, the proof's real image type and size, and that the record is still Pending. The reference / proof fields show only for the methods that need them, from the same BillingRecord lists the server rule reads. {% endcomment %}
