{% comment %} The bulk-price ladder, shared by the Add and Edit Product modals. Parameters: which "add" or "edit"; every element id is built from it rows [{"min_quantity": ..., "unit_price": ...}, ...] to open with — the stored tiers on Edit, the posted rows on a redisplay, [] on a fresh Add. The page JS pads the ladder out to three rows either way. Each row is one price break: buy at least this many, pay this much per unit. Rows post as parallel tier_min_quantity / tier_price lists — the same shape the PO modal's line items use — and inventory.views._parse_price_tiers validates the ladder as a whole. A completely blank row is ignored, so the spare rows are safe to leave empty. The rows are built by tierAddRow() in product_list.html, never rendered here, so a fresh Add, an Edit and a rejected save all go through one path. They are seeded from json_script rather than value="{{ }}" on purpose: the JSON carries a plain "1650.00", where template output would localise it to "1,650.00" and the number input would silently blank it — the trap the PO modal documents. The grid is inline and fixed at three columns rather than .grid-2, which stacks on a phone and would split each row's quantity from its price. {% endcomment %}
A lower price per unit once a customer buys enough — e.g. ₱48 each for 10 or more. Each break must be cheaper than the one before it. Leave the rows empty if this product has no bulk pricing.
